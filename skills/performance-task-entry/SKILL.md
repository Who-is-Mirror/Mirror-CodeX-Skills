# 绩效任务填报

把周报和日报归并成可追溯的绩效草稿，先交给用户检查；只有用户检查完成并再次通知后，才后台写入绩效系统并停在“待提交”状态。

本流程不使用 Edge 设置页中的浏览器调试开关。该开关关闭是正常状态；既不检查、提示或修改它，也不等待用户在浏览器里确认授权。浏览器自动化只连接由启动参数创建的独立后台 Edge。

## 不可越过的边界

- “确定”只用于保存一条待提交记录；“提交审核”是最终提交，绝不在本技能中点击。
- 草稿生成和浏览器填写是两个独立阶段。初次要求“生成绩效草稿、填写月度绩效或填写绩效”只执行前置检查和草稿阶段；草稿输出后必须停止。
- 只有用户检查草稿后再次明确说“开始填写、检查完成、按这个填写”等，才授权连接业务页面并点击“确定”。初次请求中的“填写”不能越过这道二次确认。
- 不修改或删除已有记录。同一月份、同一项目已有记录且与用户确认草稿逐字段一致时，可把它视为本次流程已完成项并自动续填其余项目；只要有一项不同就停止并报告冲突。
- 账号密码只允许来自用户当前明确提供的内容，或用户明确授权建立的本机加密凭据库；不得从历史对话、Edge 密码库、普通文件或日志中提取。明文不得写入技能文件、绩效草稿、临时脚本、日志或截图，也不得在回复中复述。
- 不控制系统鼠标，不读取或修改日常 Edge 的调试设置，不关闭用户 Edge，不操作与本次任务无关的标签页。

## 工作流

只使用本技能提供的固定入口；不要临时拼接一长串检查命令，不要按标签序号选页面，不要为每批项目新写 `fill_*.js`。固定入口为：

- `scripts/doctor.py`：严格依次执行环境依赖和加密凭据两道硬门禁；两者都通过后才诊断端点。
- `scripts/probe_browser.py`：自动启动并只读测试专用 Edge，完成后自动断开且不留下 Playwright 日志。
- `scripts/discover_sources.py YYYY-MM`：查找目标月的统一周报和日报归档。
- `scripts/revise_work_days.py <work-draft.json> --ordered <按当前项目顺序的工时...>`：按用户给出的顺序确定性修改项目工时并回报精确映射；也可用完整的 `--set PROJECT=DAYS...`。
- `scripts/finalize_draft.py <work-draft.json> --output-dir <当前任务绝对路径>/outputs`：校验、生成完整审阅文档、归档、计算哈希，并在当前任务输出目录交付可直接查看的普通文件。
- `scripts/fill_draft.py <archived-draft.json> --expected-sha256 <hash> --output-dir <absolute-output-dir>`：登录、查重、逐条填写、重试、截图、结果归档和断开。

运行时路径由 `scripts/runtime_paths.py` 统一解析：默认从本技能的安装位置推导 Codex 目录、主来源归档 `$CODEX_HOME/artifacts/akbs-member-ops`、只读回退归档 `$CODEX_HOME/artifacts/android-knowledge-intake` 和草稿归档，并从该目录推导 Windows 用户目录。专用 Edge 默认用 `--remote-debugging-port=0` 自动分配端口，后续脚本只从该专用用户目录的 `DevToolsActivePort` 解析实际 endpoint；在 WSL 中优先读取直接挂载路径，遇到 Codex 桌面包文件系统重定向时通过 PowerShell 读取同一 Windows 逻辑路径。复用前先确认该目录只有一个根浏览器进程，再校验调试模式，以及实际 `127.0.0.1` 连接对应的全部监听 PID；`::1` 监听不能证明 IPv4 端点归属。需要共享归档、非标准安装或受控排障固定端口时，只在本次命令环境显式设置覆盖变量；完整变量和浏览器默认值见[后台浏览器与页面流程](references/site-workflow.md)。`doctor.py` 会输出已解析的非敏感配置、双来源根和可用的成员身份，凭据内容不会输出。

### 前置门禁

1. 每次开始流程都必须首先运行 `python3 scripts/doctor.py`，不得用此前任务的检查结果代替。该入口严格按顺序执行以下两步；在它返回 `ready_for_draft: true` 且退出码为 `0` 之前，禁止运行 `probe_browser.py`、`discover_sources.py` 或任何草稿生成/浏览器命令。
2. 第一步是环境依赖检查：按 [后台浏览器与页面流程](references/site-workflow.md) 判断 Node.js、npm、`playwright-cli`、Python 3 和 Python 包 `cryptography`。缺少任何依赖时，脚本以退出码 `2` 停止且不会执行凭据检查；一次列全缺项并询问是否允许协助自动安装，只有用户明确同意后才能安装。安装后必须从 `doctor.py` 重新开始检查。
3. 第二步是账号密码检查：仅当第一步全部通过时，`doctor.py` 才实际解密并验证本机凭据库。缺失、损坏或无法解密时以退出码 `3` 硬阻塞，直接请用户在对话中提供账号和密码；不得因专用 Edge 中可能存在 token 而跳过。收到后由 Codex 自行通过交互式标准输入写入加密凭据库并验证，不得要求用户打开终端或手动执行命令。只有自动保存失败时，才能把手动命令作为明确标注的备用方案。保存后必须重新运行 `doctor.py`，直到两道门禁均通过。
4. 两道门禁均通过后才读取 `$playwright-cli` 并运行 `scripts/probe_browser.py`。脚本自动启动或复用专用 Edge、只读连接并立即断开；此时不登录、不填写。失败时报告脚本的具体错误并停止，不自行切换连接方式，也不检查浏览器调试开关。
5. 明确目标月份。以上各项齐备后才能读取周报日报或生成草稿。

### 阶段 A：生成绩效草稿

1. 先运行 `scripts/discover_sources.py <目标月份>`；必须首先读取它列出的统一归档，不得先在 Documents 中按文件名猜测，更不得因首次文件名检索未命中就声称“周报缺失”。脚本只读取 `submitted` 归档，优先新 AKBS 根、再只读旧根；它只接受当前成员的有效替换链叶子。若成员身份无法安全解析或归档中有多个 alias，停止并请用户设置 `PERFORMANCE_MEMBER_ALIAS`，不得混合成员来源。统一归档没有周报时，才读取用户引用的 Codex 任务或用户明确提供的路径。
2. 完整读取 `weekly_report_sources`；有效周报是项目归并、状态和成果结论的主来源。`weekly_fact_sources` 仅用于补充周报事实，或在没有有效周报时作为回退；若 `weekly_fact_omitted_count` 非零，先报告 `weekly_fact_warnings`，不得用被省略的共享 facts 补充事实。再读取脚本列出的目标月日报，仅用于补齐周报未覆盖的日期、月底零散工作和必要细节，或核对时间与结果；日报不得覆盖周报结论。
3. 用户引用了 Codex 任务时，读取任务实际内容，不得只根据标题或摘要生成绩效草稿。
4. 跨月周报只取目标月份内的工作；按项目语义去重，避免同一事项在周报和日报中重复出现。
5. 只提取已经完成、已解决、已归档或已有明确完成验证的事实。无论来自 JSON 还是 Markdown，都明确排除 `tomorrow_plan`、`next_week_plan`、`remaining`、`remaining_items`、明日/下周计划，以及“处理中”“待验证”“阻塞”“未完成”等状态的事项；它们不能写入绩效 `work_results`。
6. 按 [绩效草稿数据契约](references/performance-draft-schema.md) 在当前任务 `work/` 形成 v3 JSON；必须填写工时依据，并把每个独立成果拆成 `work_results` 的单独一项。
7. 只运行 `scripts/finalize_draft.py <work-draft.json> --output-dir <当前任务绝对路径>/outputs` 完成校验、归档与交付。该脚本会在统一归档保存版本，并在当前任务 `outputs/` 生成必交付的 Markdown 审阅文档和 JSON 普通文件，返回归档路径、交付路径、来源与工时依据和 SHA-256；不生成“审阅说明”或附录。不得再手工复制、改名、另写简化版或使用 `ln -s`/符号链接交付。
8. 最终回复使用脚本返回的 `delivery_review_path` 和 `delivery_draft_path` 给出两个可点击链接，只简述项目工时映射、合计、`draft_path` 和 SHA-256，并说明等待检查；完整日期、描述、成果和来源让用户直接查看 Markdown，不在回复中重复展开。然后停止，不得在同一轮进入绩效页面。
9. 用户要求修改工时时，不得用 `apply_patch`、文本替换或按“第一个相同数字”定位。若用户只给出一串数字，严格按当前草稿 `entries` 的既有顺序运行 `scripts/revise_work_days.py ... --ordered`；若用户明确写出项目，则用完整 `--set PROJECT=DAYS`。必须先采用脚本输出的 `work_days_by_project` 逐项确认映射，再重新运行 `finalize_draft.py` 生成新版本；最终简述只能引用脚本返回的映射，禁止凭记忆声称已改对。

### 阶段 B：用户确认后填写

1. 只有用户在绩效草稿之后再次明确通知开始，才能进入本阶段。使用阶段 A 返回的统一归档 `draft_path` 和用户确认的 SHA-256，不要把交付副本路径或符号链接作为浏览器填写输入，也不重新生成或偷偷润色内容。
2. 不手工 attach、选择标签或填写表单。只运行 `scripts/fill_draft.py`，传入用户确认的归档草稿、阶段 A 报告的 SHA-256，以及当前任务绝对 `outputs/` 路径。
3. `fill_draft.py` 自动启动专用 Edge、验证 token 或解密登录、按来源定位绩效页面、查重、逐字段回读、每项最多重试三次、保存、核验、截图、写入统一命名的 `fill-result` 并断开；临时 runner 和 Playwright 日志只存在于临时目录并自动删除。
4. 已有记录与确认草稿完全一致时脚本自动续填其余项目；已有记录存在差异时脚本在新增前阻塞，绝不覆盖或删除。
5. 若脚本返回普通 DOM 超时且没有业务冲突、验证码或字段差异，在同一轮按原命令再运行一次，不需要用户重复说“继续”。第二次仍失败才报告；不得退回临时 `nth()`/标签序号脚本。

## 内容整理规则

- 绩效草稿一项目一条记录；同一项目的周报和日报事项去重后形成成果列表。
- `任务描述` 用一句话概括项目阶段目标，不把成果全文重复进去。
- `工作成果` 的一个数组元素只能表达一个可独立列出的成果。每完成、修复、定位、验证、适配或交付一项，就单独新增一个元素；不得为了减少编号而用分号、顿号、多个句子或“并完成/并修复/并定位”等方式把多项成果塞进同一元素。
- 审阅文档和绩效系统统一把 `work_results` 展开为连续的 `1. ...`、`2. ...`、`3. ...`、`4. ...`、`5. ...`；实际编号数量按事实决定，不限制为五项，也不得把多个事实压进一个编号。
- 未完成、等待反馈或仅计划中的事项不进入 `工作成果`；可以准确描述已经完成的阶段性结果，但不得附带未完成部分，也不另设“审阅说明”。
- 项目代码必须能在系统下拉项中精确找到。系统自动带出的“项目归属”只校验，不猜测或覆盖。
- 任务类型默认沿用证据或用户指定；没有明确证据时建议“计划任务”，但在写入前向用户披露。
- 所有项目工时之和必须等于用户确认的当月工时口径；不得因为项目多就自动均分。

## 账号门禁

- 用户明确要求保存账号密码后，允许使用 [绩效系统凭据库](references/credential-vault.md) 持久化 AES-256-GCM 密文；在本技能因凭据库缺失或损坏而索取凭据后，用户在对话中同时提供账号和密码，也视为授权保存到该专用凭据库，除非用户明确要求仅本次使用。技能、草稿、结果和临时脚本中仍不得出现明文。
- 收到账号和密码后，由 Codex 启动 `credential_vault.py store --interactive`，并通过交互式标准输入依次提供；不得让用户自行输入命令，不得把凭据放入命令参数、命令文本、脚本、环境变量或可回显日志。保存后只报告状态，不复述账号或密码。
- 正常运行先复用经只读接口验证的现有 token；只有 token 失效时才在登录进程内解密凭据。不得为了测试而主动重新登录。
- 复用 token 只属于两道前置门禁通过后的登录优化，不能替代第二步凭据检查，也不能作为缺少本机加密凭据库时继续生成草稿的理由。
- 凭据库缺失、损坏或服务端拒绝凭据时才重新索取；不得回退到历史对话、浏览器密码库或搜索本地文件。
- 用户要求替换或清除凭据时按凭据库参考执行。清除是不可恢复操作，必须有当次明确授权。
- 登录成功后才截图，避免截图包含用户名、密码或密码管理器界面。

## 失败处理

- 任何表单字段回读不一致：不要点击“确定”，保留页面并报告差异。
- 保存后列表核验不一致：立即停止后续录入；不擅自编辑或删除已保存记录。
- 页面结构变化、目标月份不可选、项目不存在或出现验证码：停止并截图说明，不使用模糊定位强行继续。
- 专用后台 Edge 启动或连接失败：报告端口、进程或端点的具体诊断并停止。专用目录已有其他调试模式、多个根进程，或现有根进程的端点无法验证时，必须在清理状态文件和启动前停止。旧 `DevToolsActivePort` 不能单独证明归属；非专用或归属不明的监听不得复用。显式固定端口在没有专用根进程时，必须确认该端口所有地址均无 TCP 监听才可启动。不得引导用户更改浏览器调试开关，不得自动修改用户日常 Edge 设置，也不得批量终止 Edge 进程。

## 完成回报

阶段 A 必须使用当前任务 `outputs/` 下的真实普通文件提供审阅 Markdown 和 JSON 两个可点击链接，不得链接统一归档或符号链接；回复只简述项目工时、合计、统一归档 `draft_path`、SHA-256 和“等待用户检查，尚未操作绩效页面”，不得重复粘贴完整成果。阶段 B 只简述保存或自动识别为一致的项目与工时、失败项、`fill-result` 和截图，并明确“未点击提交审核”。
