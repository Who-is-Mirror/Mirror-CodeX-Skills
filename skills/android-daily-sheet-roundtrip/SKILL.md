# Android Daily Sheet Roundtrip

Keep the two stages strictly separate:

1. **Stage A — sessions to sheet draft.** Require fresh consent for the exact report date, load the newest installed `android-daily-report-intake` skill, and follow its normal semantic session-review and v4 facts-generation process. The resulting facts are the daily report content; the sheet is only an editable A:F view of those same facts. Then write and screenshot the dated sheet through the existing background Edge CDP session. Do not prepare a report or create Markdown, `report_view`, or pending material. Stop after the screenshot and wait for the user.
2. **Stage B — edited sheet to pending report.** Enter only when the user explicitly says the sheet edits are complete or asks to reverse-generate the daily report. Use `scripts/run_stage_b_fast.mjs` so one model snapshot supplies the structural audit, formatting/object checks, screenshot and facts conversion; do not perform separate per-cell audit and converter reads. Compare with the exact Stage A `stage-a-sheet-snapshot.json`: accept ordinary text edits, identify complete task/scope deletions for confirmation, and block partial structural deletion. Confirmation ledgers must use `android-daily-sheet-change-decisions-v2` and match the exact baseline/current snapshot hashes. Never repair or reinterpret damaged content silently. Every user-authorized restoration, renumbering, omission cleanup, or consistency rewrite must first be written into the enterprise WeChat sheet itself with `scripts/apply_daily_sheet_repairs.mjs`; a repair made only in facts, JSON, or Markdown is invalid. A confirmed complete deletion must also remove its now-blank physical rows with `scripts/compact_daily_sheet_rows.mjs`; do not leave a visual hole between the surrounding semantic blocks. After any repair, run the fast Stage B path once more and use only that final PASS snapshot for v4 facts, the current customer guard, and daily intake `--prepare`. Validate the exact package and audit it against the repaired sheet, then give the user a clickable absolute local link to that package's `reports/daily.md` for preview. The final handoff must separately disclose every accepted user modification and every repair performed, using `无` when either list is empty, so the user can judge the final report. Do not submit without a separate explicit authorization.

Read [references/two-stage-workflow.md](references/two-stage-workflow.md) before either stage. For Stage A session collection, also read [references/incremental-session-review.md](references/incremental-session-review.md). For any sheet creation or rendering, read [references/sheet-template-contract.md](references/sheet-template-contract.md). Before every Stage B conversion or repair, read [references/sheet-recovery-matrix.md](references/sheet-recovery-matrix.md) and run `scripts/audit_daily_sheet_changes.mjs` against the exact Stage A baseline. Use the scripts and canonical fake-data asset there; never copy, fork, or modify the current plugin's session merge, scope inference, facts normalization, or report rendering logic.

Stage A must not treat the automatic output of `scripts/draft_daily_from_sessions.py` as report content. That script is a privacy-minimized candidate/diagnostic pass only. Use it to expose plugin drift, unresolved identity, and coverage hints. Build a complete date-bounded active-and-archived task index, then use `scripts/session_review_cache.py` only to avoid rereading unchanged task bodies. Its cache is valid only when the current daily plugin version, intake instructions, facts contract, semantic implementation modules, and exact task revision all match. A cache hit reuses compact evidence, never final scope or facts decisions. Re-run the current daily intake semantic merge across all current evidence on every Stage A run and form one `akbs-daily-work-facts-v4` file under the run output directory. Titles and retrieval summaries may select candidates but are not evidence. Merge repeated handling, split independent work, keep the latest verified result/status, and omit report-generation chatter and raw paths exactly as the current daily intake requires. Run the customer guard against these facts before converting them. `facts_to_sheet_rows.py` deliberately rejects automatic candidate envelopes and task-evidence caches.

All sheet access uses Playwright against the user-owned background Edge CDP endpoint (default `http://127.0.0.1:9223`). Before either stage, run `scripts/check_browser_prerequisites.mjs`; reuse its verified `playwright_module` for every browser script in that stage. The resolver prefers the Codex-bundled runtime, then an already approved local runtime, and normalizes both ESM and CommonJS package exports. Do not create ad-hoc bridge modules or symlinks, guess `index.js` versus `index.mjs`, or install anything while a verified runtime exists. If Playwright or Node/npm is absent, stop and request the user's explicit installation approval with the proposed local target and command. If CDP is unavailable, stop and request permission or user action to start/restart Edge with the remote-debugging endpoint. Do not scan sessions while either prerequisite is unresolved.

Do not use a bot/CLI sheet API, foreground mouse control, or `browser.close()`. Fail closed on plugin or enterprise WeChat internal API drift, ambiguous identity, GMS loss, unexpected sheet structure, duplicate date tabs, or failed screenshot verification.

Before scanning sessions or creating a workbook, run `scripts/check_wecom_login.mjs`. It is a read-only login gate and must never clear cookies or storage. When already logged in, continue. When login is required, capture only `.wwLogin_qrcode_img` once, show that exact QR image to the user, and stop Stage A. On a later restart request, rerun the same check so an expired QR is refreshed and captured once; continue only after it returns `PASS`.

Use one managed enterprise WeChat workbook titled `Android 日报草稿` for ordinary Stage A runs. Persist its document ID, stable title, and URL outside the skill at `$CODEX_HOME/report/android-daily-managed-workbook.json`; create and register a workbook only when that state is absent or the user explicitly requests a reset. Before rendering, run `scripts/prepare_daily_sheet_tab.mjs` for the exact date. It retains at most five date-named worksheets, orders them newest to oldest, adds a blank date worksheet while fewer than five exist, and replaces the oldest date worksheet once the limit is reached. Replacing an already-present target date requires the user's explicit regenerate request and `--replace-existing`. Reject mixed non-date tabs, duplicate dates, ambiguous deletion targets, or failed ordering instead of deleting uncertain data.

After the target date tab is prepared and blank, run `scripts/render_daily_sheet_fast.mjs`. The fast renderer snapshots the existing clipboard, writes one `text/plain` TSV plus one `text/html` table, activates only the exact target date tab and sends one Playwright `Control+V`. If the workbook model remains blank, it rewrites the same dual-MIME payload, reselects A1, and retries `Control+V` exactly once before invoking the verified enterprise WeChat paste action once. If that loader is capability-gated and still writes nothing, call the same loaded paste module's bottom `apiDoPaste` batch entry once; do not repeat loader discovery or switch to per-cell writes. It then applies all calculated row heights and column widths through one dimension batch. If the model is still blank at that exact point, it repeats the ordinary dual-MIME A1 paste once after the dimension batch and reapplies dimensions before the final audit. It audits values/format/merges, restores the clipboard, captures screenshots, and writes `stage-a-sheet-snapshot.json` from that same model audit; this exact snapshot is the Stage B value/layout baseline, so do not spend another browser pass recapturing it. `assets/daily-sheet-template.json` is the local source of truth; screenshots are verification evidence only. Keep `scripts/render_daily_sheet.mjs` only as an explicitly chosen compatibility path for a nonblank workbook or after the user accepts a reported fast-path incompatibility; never silently fall back to slow coordinate-based formatting.
